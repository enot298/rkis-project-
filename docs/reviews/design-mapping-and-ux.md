Составляет ДИ (Баранов А.). Макеты каркасов — `design/mockups/`, веб-страницы — REQ-WEB-001…006.

## 1. Макет → элемент → поле модели

| Макет | Элемент | Поле модели | Статус |
|---|---|---|---|
| Список заказов | № | `Order.id` | есть |
| | Клиент | `Order.client.name` | есть |
| | Дата | `Order.date` | есть |
| | Статус (цветная метка) | `Order.status` (+ `get_status_display`) | есть |
| | Сумма | `Order.total_amount` | есть |
| | Метка «требует подтверждения» | `Order.needs_approval` | есть |
| Детали заказа | Таблица позиций | `OrderItem` (товар, количество, цена, сумма) | есть |
| | Блок платежа | `Payment` | есть |
| | История изменений | — | нет (план: блок 6) |
| Форма заказа | Выпадающий список клиентов | `Client.__str__` | есть |
| | Динамический список товаров | `Product`, `OrderItem` | есть |
| | Заметки | `Order.notes` | есть |
| Отмена | Поле «Причина» | `Order.cancel_reason` | есть |
| Состояние empty | «Заказов пока нет» | пустой набор | опоры в данных не нужно |
| Состояние error (BR-001…004) | Тексты ошибок | сообщения в `clean()` | есть |
| Дашборд | Количество, суммы, статусы | агрегаты по `Order` | есть (запросы) |
| Мобайл: карточка заказа | номер, клиент, статус, сумма | `Order`, `Client` | есть |
| Мобайл: скан | штрихкод | `Product.barcode` | есть |

## 2. UX-чек-лист ревью админки

Заполняется при просмотре админки на загруженных фикстурах. Результат: ✔ ок, ✘ замечание.

| № | Что проверяем | Предварительная оценка по коду | Результат ревью |
|---|---|---|---|
| 1 | Списки: достаточно колонок и нет перегруза (≤ 8) | Заказы — 9 колонок, на грани; остальные 4–6 | |
| 2 | Группировка полей в карточках (fieldsets) логична | «Основное → Сумма → Заметки → Служебное» | |
| 3 | Поиск есть везде, где нужен (клиент, телефон, логин, товар, штрихкод) | есть | |
| 4 | Фильтры полезны (статус, подтверждение, архив, дата, менеджер, остаток) | есть, для остатков своя группировка | |
| 5 | Статусы человекочитаемые, не коды | да | |
| 6 | Даты в формате `дд.мм.гггг` (язык `ru`) | да | |
| 7 | Деньги с копейками и знаком ₽ в подписи столбца | подпись «Сумма, ₽» | |
| 8 | Обязательные поля отмечены, подсказки к ним понятны | стандартные для Django | |
| 9 | Служебные поля только для чтения | `created_at`, `updated_at`, `version`, `total_amount` | |
| 10 | Названия разделов: «Клиенты», «Товары», «Заказы», «Платежи», «Пользователи», «Сеансы входа» | да | |
| 11 | Массовые действия понятно названы | «Перевести в статус…», «Отправить в архив» | |
| 12 | Поведение пустых необязательных полей (email, адрес, штрихкод) | допустимо пустыми | |
