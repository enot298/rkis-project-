# Данные для десктопа и мобайла

Составляют ДР и МР (Шукуров С.). **Черновик с предварительными выводами: Сарвар проверяет и подтверждает или правит.** Результат войдёт в требования к сериализаторам (блок 6).

## Десктоп (бухгалтер)

| Функция | Таблица | Поля | Назначение | Есть в модели? |
|---|---|---|---|---|
| REQ-DESK-001 Печать отчёта | order, client, order_item, product, payment | номер, дата, клиент, статус, сумма, позиции, платёж | Печатный отчёт по заказам | да |
| REQ-DESK-002 Экспорт за период | order | `date`, `status`, `total_amount`, `client.name` | Выгрузка в CSV/Excel | да (индекс по `date`) |
| REQ-DESK-005 Поиск | order, client | `id`, `client.name`, `date` | Поиск по номеру, клиенту, дате | да |
| Сводные отчёты | order, payment | `total_amount`, `status`, `payment.amount`, `payment.status`, `paid_at` | Суммы по статусам, оплаты за период | да, считаются запросами (`Sum`, `Count`); отдельные поля не нужны |
| REQ-DESK-004 Офлайн-кеш | order, client, product | `updated_at`, `version`, `id` | Синхронизация без дублей | частично (см. замечание 2) |

Агрегаты (сумма за период, количество по статусам) считаются запросами на сервере. В модели их хранить не нужно.

**Объёмы.** Типы полей достаточны для малого бизнеса: `BigAutoField` у ключей, `DECIMAL(10,2)` для денег (до 99 999 999,99 ₽). Для объёмов порядка десятков тысяч заказов индексы по дате и статусу есть.

**Замечания:**
1. Подтверждаю: печать и экспорт обеспечены данными.
2. Позиции и платежи не имеют `updated_at`, поэтому для офлайн-кеша заказа ориентироваться на `Order.updated_at` (оно обновляется и при изменении позиций). `Order.version` при изменении позиций не растёт: клиенту нужно сравнивать `updated_at`.
3. Нужен список клиентов и товаров для фильтров: данные есть.

## Мобайл (кладовщик)

| Функция | Таблица | Поля | Назначение | Есть в модели? |
|---|---|---|---|---|
| Карточка заказа в списке | order, client | `id`, `client.name`, `date`, `status`, `total_amount` | Компактная карточка | да |
| REQ-MOB-001 Сканирование | product | `barcode` | Поиск товара по штрихкоду | да (добавлено в v1.1) |
| REQ-MOB-003 Геолокация | order | координаты отгрузки | Место отгрузки при смене статуса | **нет** |
| REQ-MOB-002 Push | user | токен устройства, настройка «вкл/выкл» | Уведомления | **нет** |
| REQ-MOB-004 Офлайн-кеш 50 заказов | order | `id`, `updated_at`, `version` | Кеш и очередь отправки | да (`id` уникален, есть `version`) |
| REQ-MOB-005 Биометрия | session | `token`, `expires_at` | Быстрый вход по сохранённому токену | да (хранение токена — на устройстве) |
| Фото | — | — | В требованиях фото нет | не требуется |

**Недостающее и план:**
1. Координаты места отгрузки: добавить в `Order` поля `shipment_latitude`, `shipment_longitude` (`DECIMAL(9,6)`, NULL). Схема v1.2, до блока 9.
2. Push: нужна таблица устройств (пользователь, токен, платформа, вкл/выкл). Решить в блоке 10.
3. Состав карточки списка совпадает с макетом ДИ (номер, клиент, дата, статус, сумма).
